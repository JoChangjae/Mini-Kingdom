## 2. 클라이언트 (게임 엔진)

### 2.1 게임 엔진: Unity 2022 LTS

| 항목 | 선택 | 이유 |
|------|------|------|
| **엔진** | Unity 2022.3 LTS | 모바일 게임 업계 표준, 2D 지원 우수, 에셋 생태계 |
| **렌더링** | URP (Universal Render Pipeline) | 모바일 최적화, 2D 라이팅 지원 |
| **스크립팅** | C# (.NET Standard 2.1) | Unity 표준, 생산성 높음 |
| **물리** | 2D Physics (Box2D) | 가벼운 2D 물리 |

**Unity 선택 이유:**
- ✅ 크로스 플랫폼 (iOS/Android) 동시 개발
- ✅ 2D 게임 제작에 최적화된 도구 (Tilemap, Sprite, Animator)
- ✅ 방대한 에셋 스토어 (프로토타이핑 속도 향상)
- ✅ 풍부한 레퍼런스, 커뮤니티
- ✅ 광고 SDK, IAP 네이티브 지원

### 2.2 핵심 라이브러리

| 라이브러리 | 용도 | 비고 |
|-----------|------|------|
| **UniTask** | 비동기 처리 | async/await 기반, GC 최소화 |
| **UniRx** | 리액티브 프로그래밍 | UI 바인딩, 이벤트 스트림 |
| **DOTween** | 트윈 애니메이션 | UI/캐릭터 연출 |

| **Addressables** | 에셋 관리 | 번들링, 원격 에셋 로드 |
| **Cinemachine** | 카메라 | 2D 카메라 추적, 쉐이크 |

## 3. 클라이언트 아키텍처

### 3.1 아키텍처 패턴

```
┌─────────────────────────────────────────────────────────┐
│                    Presentation Layer                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐       │
│  │   View   │  │   View   │  │  View (UI/Scene) │       │
│  │ (Kingdom)│  │ (Dungeon)│  │   (Result, etc.) │       │
│  └────┬─────┘  └────┬─────┘  └────────┬─────────┘       │
│       │              │                 │                 │
│  ┌────┴──────────────┴─────────────────┴──────────┐      │
│  │              ViewModel / Presenter             │      │
│  │          (UniRx Observable Binding)            │      │
│  └────────────────────┬──────────────────────────┘      │
├───────────────────────┼─────────────────────────────────┤
│                 Service Layer                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ Dungeon  │  │ Kingdom  │  │ Combat   │               │
│  │ Service  │  │ Service  │  │ Service  │               │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘               │
│       │              │              │                    │
│  ┌────┴──────────────┴──────────────┴────────────┐       │
│  │             Game State Manager                │       │
│  │         (Singleton, Event-driven)             │       │
│  └───────────────────┬──────────────────────────┘       │
├──────────────────────┼──────────────────────────────────┤
│                 Data Layer                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ Local    │  │ Remote   │  │ Config   │               │
│  │ Save     │  │ API      │  │ (ScriptO)│               │
│  │ (JSON)   │  │ (Firebase│  │          │               │
│  └──────────┘  └──────────┘  └──────────┘               │
└─────────────────────────────────────────────────────────┘
```

### 3.2 핵심 설계 원칙

1. **MVVM 패턴** — View ↔ ViewModel 분리로 테스트 용이성 확보
2. **ScriptableObject 기반 데이터** — 몬스터, 아이템, 시설 데이터를 SO로 관리
3. **이벤트 드리븐** — `UniRx` 기반 옵저버 패턴으로 느슨한 결합
4. **상태 머신** — 게임 상태 (왕국 ↔ 던전 ↔ 전투) 전환 관리
5. **오브젝트 풀링** — 몬스터, 탄환, 이펙트 풀링으로 GC 최소화

### 3.3 던전 생성 시스템

```csharp
// 절차적 던전 생성 파이프라인
DungeonGenerator
├── RoomTemplateDB        // ScriptableObject 기반 방 템플릿
├── RoomSequencer         // 방 순서 결정 (난이도 곡선)
├── TilemapBuilder        // Rule Tile 기반 맵 렌더링
├── EnemySpawner          // 몬스터 배치 (웨이브 패턴)
└── LootTableResolver     // 보상 결정 (가중 랜덤)
```

## 4. 서버 & 백엔드

### 4.1 서버리스 아키텍처 (Firebase)

**초기에는 서버리스로 시작**, 유저 규모에 따라 전용 서버로 마이그레이션

| 서비스 | Firebase 제품 | 용도 |
|--------|--------------|------|
| **인증** | Firebase Auth | Google/Apple/Guest 로그인 |
| **데이터베이스** | Cloud Firestore | 유저 데이터, 왕국 상태, 인벤토리 |
| **실시간 기능** | Realtime Database | 랭킹, 이벤트 타이머 |
| **서버 로직** | Cloud Functions | 결제 검증, 랭킹 집계, 치트 방지 |
| **파일 저장** | Cloud Storage | 패치 에셋, 유저 프로필 이미지 |
| **알림** | Cloud Messaging (FCM) | 푸시 알림 (건설 완료, 이벤트) |
| **원격 설정** | Remote Config | A/B 테스트, 밸런스 핫픽스 |
| **분석** | Google Analytics + BigQuery | 유저 행동 분석, 리텐션 추적 |
| **크래시** | Crashlytics | 크래시 모니터링 |

### 4.2 데이터 구조 (Firestore)

```
users/{userId}
├── profile
│   ├── displayName: string

│   └── lastLogin: timestamp
├── kingdom
│   ├── level: number
│   ├── buildings: map
│   │   ├── blacksmith: { level: 3, state: "idle" }
│   │   ├── magicTower: { level: 2, state: "upgrading", completeAt: timestamp }
│   │   └── ...
│   └── layout: array  // 건물 배치 좌표
├── inventory
│   ├── resources: map { gold: 1250, wood: 340, stone: 120, ... }
│   ├── equipment: array
│   └── items: array
├── progress
│   ├── dungeonsCleared: map
│   ├── achievements: array
│   └── collection: map  // 도감
└── stats
    ├── totalRuns: number
    ├── totalBossKills: number
    └── playTime: number
```

### 4.3 보안 & 치트 방지

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   클라이언트   │ ──→ │ Cloud Func.  │ ──→ │  Firestore   │
│  (런 결과전송) │     │ (결과 검증)   │     │  (데이터저장) │
└──────────────┘     └──────────────┘     └──────────────┘
```

- 런 결과를 서버에서 검증 (비정상 수치 탐지)
- 자원 변경은 Cloud Functions를 통해서만 가능
- 클라이언트는 읽기 위주, 쓰기는 서버 함수 경유

## 5. DevOps & CI/CD

### 5.1 버전 관리

```
GitHub Repository
├── main          ← 릴리스 브랜치
├── develop       ← 개발 브랜치

└── release/*     ← 릴리스 준비
```

### 5.2 CI/CD 파이프라인

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  코드 푸시 │ →  │  GitHub  │ →  │  Unity   │ →  │  스토어   │
│  (GitHub) │    │  Actions │    │  Cloud   │    │  배포     │
│           │    │  (테스트) │    │  Build   │    │ (iOS/And)│
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

| 단계 | 도구 | 내용 |
|------|------|------|
| **코드 검사** | GitHub Actions | 린트, 유닛 테스트 |
| **빌드** | Unity Cloud Build | iOS/Android 자동 빌드 |
| **테스트** | Firebase Test Lab | 실기기 자동 테스트 |
| **배포** | Fastlane | 스토어 자동 업로드 |
| **모니터링** | Crashlytics + Analytics | 크래시/성능 모니터링 |

### 5.3 에셋 관리

```
Addressables (에셋 번들)
├── 로컬 번들 (초기 설치)
│   ├── 핵심 UI
│   ├── 기본 던전 (수풀 숲)
│   └── 기본 캐릭터/몬스터
└── 원격 번들 (추후 다운로드)
    ├── 추가 던전
    ├── 이벤트 에셋
    └── 시즌 콘텐츠
```

**초기 설치 용량 목표: 150MB 이하**

## 6. 성능 최적화 전략

### 6.1 모바일 최적화 목표

| 항목 | 목표 |
|------|------|
| **프레임** | 60 FPS (저사양 30 FPS) |
| **메모리** | 300MB 이하 |

| **발열** | 장시간 플레이 시 미온 유지 |
| **로딩** | 씬 전환 2초 이내 |

### 6.2 최적화 기법

| 영역 | 기법 | 세부 내용 |
|------|------|-----------|
| **렌더링** | Sprite Atlas | 스프라이트 아틀라스로 드로우콜 최소화 |
| **렌더링** | Camera Culling | 화면 밖 오브젝트 렌더링 제외 |
| **메모리** | Object Pooling | 몬스터/이펙트/탄환 풀링 |
| **메모리** | Addressables | 필요 시 에셋 로드/언로드 |
| **CPU** | Job System | 경로 탐색, 충돌 처리 멀티스레드 |
| **GC** | UniTask | Task 대신 UniTask로 힙 할당 최소화 |
| **네트워크** | 배치 처리 | API 호출 묶음 처리 |
| **저장** | 델타 저장 | 변경분만 서버에 동기화 |
